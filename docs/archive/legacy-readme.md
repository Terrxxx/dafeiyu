# 大肥鱼 · QQ × B站自主社交伙伴

这是一个在本机运行的 Node.js 项目：DeepSeek 负责决定如何聊天和分享，NapCat / OneBot 11 负责 QQ 收发，B站网页接口负责热门视频、字幕、@通知和评论。当前通过 DeepSeek Harness SDK 驱动模型与工具循环，QQ/B站接口和定时触发由本项目适配；本项目不是 DeepSeek 官方产品。

## 已实现

- 撤回：`qq_list_sent` 查询当前允许会话中自己已确认发出的消息，`qq_recall_message` 按真实消息ID撤回；保留最近500条回执，分条发送逐条记录。仅新版本启动后记录的消息可用，不猜测旧消息ID，不撤回别人消息。平台超时/权限限制会报错，撤回成功后写入会话记录。
- 未回复跟进：AI 主动私聊问话可标记 `expectReply=true`（文本含问号也会识别，网址参数除外）。默认等30分钟，由下一次自主社交周期判断是否轻轻跟进一次，可以说“居然不理我”或选择不发。用户已回复、暂停联系、原问话已撤回或超过24小时均不跟进；同一问话最多一次判断和一次发送，重启也不重放。群内发言不会误算成对应私聊回复。`social.followupEnabled` 可关闭，`social.followupWaitMinutes` 可调整（至少10分钟）。需要开启原有自主社交定时器；普通聊天回复和分享不默认触发跟进。

- QQ 扩展：读取已知用户资料、自己/已知用户近期空间及页面内嵌评论；对核验后的评论回复；保存看懂的表情到 QQ 收藏；引用回复、发图片和本机中文合成语音；后台自主更换已看懂且收藏的静态头像。
- 公开搜索：独立无登录态的 Edge/Chrome 搜索与结果页文字读取，不提供任意点击、登录、文件上传或本机页面访问。

- QQ：普通账号经 NapCat 接入，允许范围内的群无需 @；私聊和群聊均先合并连续消息，再由 AI 判断是否接话。不同私聊/群的历史隔离、重启保留。
- B站：每 90 秒检查 @ 通知，每 30 分钟读取热门视频，不限定主题。
- 自主决策：模型可查询 QQ 好友/群、读取视频、自主选择是否发送 QQ 分享或发表评论。分享对象不是预先写死的。
- 扫码登录：B站手机 App 扫码，Cookie 保存在本机 `data/bilibili-auth.json`。
- 可靠性：串行任务队列、QQ重连、回复去重、持久化额度、发送状态不明时不自动重发、单实例锁、评论楼层核验。
- 本地记录：`data/actions.jsonl` 是动作审计，`data/state.json` 保存记忆和去重，`reports/` 保存每轮浏览报告。
- 图片理解：接收 QQ 图片和纯图片消息，使用当前模型描述截图、表情和梗图；最多 3 张，每张 8MB，失败时明确说明。
- 真实互动：支持 QQ 原生引用回复、@发送者、查询群成员并@指定成员，不通过拼接CQ字符串伪造消息。
- 自主任务：AI 可创建、查看和取消会话内的未来任务，到期后自动执行；重启保留任务记录。

## 图片、主动分享与自主任务

当前配置的官方 `deepseek-flash` 已用生成的红色测试图片完成真实视觉请求验证，能够识别红色色块。无需另配视觉模型。QQ图片先从QQ图片服务下载，送给当前模型识别；识别后的图片缓存到已忽略的 `data/media/`（最多2000张、1GB（1024MB）），元数据保存在本地状态中，供模型按ID选择回复或收藏。未收藏图片仅在原会话可用，主动收藏的表情可复用。本版不读取本地任意路径；失效链接会尝试通过 NapCat `get_image` 刷新。GIF的理解能力取决于模型，不保证完整理解动画。

QQ 空间凭据由 NapCat 临时提供给本地适配器，不交给模型。仅解析页面当前加载的动态和评论；无权限、登录失效或结构变化会报错，空列表不等于没有发表。自动检查自己的空间默认每10分钟一次（`social.qzonePollMinutes`，最少5分钟），首次建立基线不回复旧评论，每轮最多判断2条新发现的评论，每小时最多回复3条；`social.qzoneAutoReply=false` 可关闭。好友空间需先核实为当前发送者、已有好友或允许群的成员，不能任意猜号读取。

QQ 空间互动：`qzone_read(userId)` 查看已核实用户的近期说说，返回真实 `postRef`，随后可用 `qzone_like_post(postRef)` 点赞或 `qzone_comment_post(postRef,text)` 直接发表评论；回复已有评论继续使用 `qzone_reply_comment`。大肥鱼可以在自主社交时自行选择查看和互动，也可以选择不操作。写入需 `social.qzoneEnabled=true`，点赞每小时最多10次，评论与评论回复共用每小时3次额度，并计入总发送额度。每条动态最多主动评论一次，点赞不取消已有赞，跨重启去重；提交前重新读取核验，缺少可靠参数不猜测提交。操作和回执记录在 `data/actions.jsonl`，睡眠时不查询也不写入。新点赞、评论通过模拟请求验证，尚未实测账号写入，线上仍取决于空间权限、NapCat凭据和网页接口兼容性。

语音默认使用本地 `chaowen` 中文模型，`social.voiceName` 也可指定已安装的 Windows 系统音色；每条最多200字，临时 WAV 合成后删除，通过 NapCat record 消息发送。语音转码依赖 NapCat 的本机编码环境。头像更换仅后台自主活动可执行，24小时最多一次，候选来自已识别并收藏的静态图片；不自动生成头像。表情收藏使用 NapCat 的本地路径接口，因此本版要求 NapCat 与项目在同一台电脑。图片/语音均保留发送额度、回执和去重逻辑，给当前会话发完不会再自动追加最终文字。

头像身份限制：以用户指定的当前QQ头像为固定参考，原图与账号标识保存在已忽略的 `data/avatar-reference.json`，以后不会随自动换头像更新。`qq_set_avatar` 在执行前，将参考原图和候选原图一同送给当前视觉模型；要求明确为同一角色、单人且适合作头像，置信度至少0.95，其他角色、物品、多人、格式错误或不确定均拒绝。普通模型与Harness都传入两张实际图片，不用图片描述代替核验。QQ账号改变或参考损坏时停止更换，不自行重建参考。视觉判断仍可能误判；24小时限制、素材权限和睡眠拦截继续生效。

匿名逛店：`shopping_search(platform,keyword)` 搜索淘宝/京东，`shopping_home(platform)` 读取匿名首页可见商品，platform为taobao或jd，每小时共12次。使用独立临时浏览器，不带用户浏览器账号和Cookie；只放行平台及素材域名的只读GET请求，不开放登录、购物车、订单或支付。返回实际卡片标题、页面标价和去跟踪参数的商品链接；标价不是成交价。遇登录/验证或读取失败如实返回blocked；搜索可尝试公开搜索索引，若有结果则标为limited且价格未知，不冒充平台实时搜索或首页推荐。公开页面的可用性可能变化；本次实测淘宝首页可读，淘宝搜索、京东搜索及首页未取得完整匿名商品卡片，不能视为已实测打通。

她可自主逛店，也可向熟悉的人表达喜欢某件商品并分享真实链接；不每件都发、不重复求买、不用情绪或关系施压，不编收货地址或实际购买体验。本功能没有下单和支付接口，是否购买完全由用户决定。

浏览器自动寻找本机 Edge 或 Chrome，也可设置 `social.browserPath`。公开搜索每小时最多20次、原文读取30次；不使用用户浏览器配置，页面脚本关闭，只读搜索结果。验证码或页面无法读取时直接说明，不绕过验证。资料页、网页、空间和图片里的文字均视为外部内容，不赋予工具权限。

本轮验证：个人资料、自己的空间动态、中文语音合成、公开浏览器搜索已实测；56项自动测试覆盖完整Harness工具注册、媒体回执、空间评论核验和去重。实际空间评论发布、QQ语音/图片送达、头像修改及收藏写入采用模拟测试，未为了验收修改账号或向他人发消息。空间适配参考 [NapCat当前API](https://napneko.github.io/api/4.18.33) 和 [feeds3接口说明](https://github.com/Gu-Heping/onebot-qzone/blob/main/doc/feeds3-parser.md)，网页接口变化仍可能需要适配。

AI 可用 `qq_reply_current` 自主选择引用或@发送者，用 `qq_group_members` 查询目标群成员，再通过 `qq_send_message` 的 `atUserIds` 参数真正@成员（最多3人，不支持@全体）。工具已回复当前消息时，程序不会把最终文本再发送一次。

AI 继续每30分钟主动浏览热门，发现实际内容中有趣的地方后，自主决定是否把链接和短评分享给合适的好友或群。对同一接收对象分享相同BV视频时去重，即使文案不同也不重复。B站视频仍主要通过首分P字幕理解，新增QQ识图不等于已经支持视频画面分析。

自主任务通过 `task_create({prompt, delayMinutes})` 安排，可通过 `task_list` 查看和 `task_cancel({id})` 取消。每项为一次性任务，1分钟至7天后执行，最多12项待办，每小时最多启动6项。程序每30秒检查一次，到期后还可能等待任务队列；程序停止时不会执行，重新启动后补执行到期的待办。若进程在执行途中中断，该任务标为 `uncertain`，不自动重放可能已经发送的消息。

任务保留原会话范围，执行时可调用模型现有工具，包括继续浏览和选择分享目标；结果写入 `reports/task-任务ID.md`。只有发送工具成功才代表已通知用户，写报告不等于发了消息。任务创建和完成状态记录在 `data/actions.jsonl`。

自然聊天规则在 `persona.md`：短句接话、适度玩笑、根据上下文决定参与，不每次列清单或自我介绍，也不虚构真人身份和现实经历。

## 首次启动

### 1. 填写模型配置

首次克隆先复制 `.env.example` 为 `.env`。用文本编辑器打开它，填写：

```dotenv
DEEPSEEK_API_KEY=你的API密钥
DEEPSEEK_BASE_URL=https://api.deepseek.com
DEEPSEEK_MODEL=deepseek-flash
NAPCAT_WS_URL=ws://127.0.0.1:3001
NAPCAT_TOKEN=在NapCat中设置的相同Token
```

模型名可按自己账号可用模型修改。不要把密钥或 Cookie 发到聊天里。Node.js 24 或更新版本即可；已有环境无需 Python。

### 2. 配置 NapCat

使用 [NapCat 官方安装文档](https://napneko.github.io/guide/boot/Shell) 安装 Windows 版，登录准备作为“大肥鱼”的 QQ 账号。

在 NapCat WebUI 的网络配置中新增 **WebSocket 服务端（正向 WS）**：

| 设置 | 值 |
| --- | --- |
| Host | `127.0.0.1` |
| Port | `3001` |
| Token | 与 `.env` 中 `NAPCAT_TOKEN` 一致 |
| 消息格式 | `array`（消息段数组） |
| 启用 | 是 |

本项目主动连接此服务端。NapCat 的 WebUI 管理端口不是 OneBot 端口。运行中断开 QQ 后会每 10 秒尝试重连。项目不自动安装、修改或卸载你现有的 QQ 客户端。

### 3. 登录 B站

在项目目录运行：

```powershell
npm.cmd run login:bili
```

或双击 `login-bilibili.cmd`，使用 B站手机 App 扫终端二维码。也可打开临时图片 `data/bilibili-login.png` 扫描；登录结束后图片会删除。

二维码登录失败时，可在本机 `.env` 的 `BILIBILI_COOKIE` 填入自己的完整浏览器 Cookie（包含 `SESSDATA` 和 `bili_jct`）。此变量优先于扫码文件，重新扫码前请清空旧变量。Cookie 到期后重新登录。

### 4. 检查并运行

```powershell
npm.cmd run doctor
npm.cmd run doctor -- --online
npm.cmd start
```

也可以双击 `start.cmd`。`doctor` 只检查本地必需配置；`--online` 还会读取 B站登录状态和 NapCat 登录信息，不发测试消息。

首次启动成功后会建立 @ 通知基线，忽略历史通知。启动后约 30 秒自动开始第一轮自主浏览，**可能真实发送 QQ 消息和 B站评论**。此行为对应你要求的自主分享。后台必须保持运行；关闭终端即停止。Ctrl+C 会等当前任务结束后退出。

只运行一轮自主浏览：`npm.cmd run once`。它同样可能真实发送消息。

## 设置和人设

首次运行从 `config.example.json` 创建本地 `config.json`，示例 QQ 允许列表为空，需要填写范围或 `["*"]`。本机已有配置保持不变。修改 `config.json` 后重启；`persona.md` 控制“大肥鱼”的性格与判断方式。

| 配置 | 默认值 / 含义 |
| --- | --- |
| `qq.adminUsers` | 管理员 QQ 号字符串数组，只用于核验身份，不限制聊天对象；所有私聊和已加入的群均可聊天。旧 `allowUsers` / `allowGroups` 不再生效 |
| `qq.requireMentionInGroup` | 当前为 `false`，无需 @，每条群文本由 AI 判断是否回复；改为 `true` 时只判断 @ 消息 |
| `qq.cooldownSeconds` | 同会话两次开始生成之间至少 15 秒；新消息排队等待，不会因为冷却被丢弃；可改为 0 |
| `bilibili.allowMentionUsers` | `["*"]`，任何人的视频评论 @ 都可回复 |
| `bilibili.pollSeconds` | 90 秒 |
| `bilibili.browseMinutes` | 30 分钟 |
| `bilibili.maxVideosPerRound` | 每轮最多读取 3 个视频 |
| `agent.maxToolRounds` | 一次任务最多 6 轮模型决策 |
| `agent.maxModelCallsPerHour` | 示例为每小时 60 次；设为 `0` 不限制模型请求次数，平台自身额度仍适用 |
| `agent.maxOutgoingPerHour` | 每小时最多 20 次发送尝试，包括 QQ 和 B站 |
| `agent.maxBiliCommentsPerHour` | 每小时最多 3 次 B站评论尝试 |

禁用某个平台：将对应 `enabled` 改为 `false`。所有额度跨重启保留，是本机程序限额，不是平台承诺的安全额度。自主分享可以选择任何已查询到、符合允许列表的 QQ 好友/群；不会自动加好友、加群。一次列表最多向模型展示 150 个目标。

私聊和群聊参与判断单独调用模型，只返回是否回复，不执行工具。决定保持安静时不会发送消息，也不会占用发送额度，但消息仍进入对应会话的上下文。决定回复后再生成内容，沿用冷却、队列及发送限额。每次判断也计入 `maxModelCallsPerHour`，达到额度后会在终端报告；模型判断失败时不自动发言。

## 等待消息与主动社交

每个会话等待最后一条消息后安静 8 秒再合并，从首条开始最多等待 25 秒；之后仍可能等待队列和冷却。通过 `qq.mergeSeconds` / `qq.maxWaitSeconds` 调整。合并保留说话者；AI 可以选择不回复。关闭进程会清空尚未提交的等待消息。

`social.enabled` 开启自主社交，每 `social.intervalMinutes`（默认 10 分钟）思考一次，启动后 60 秒触发首轮，此后按间隔循环。AI 可主动在允许的群发言、给好友分享，或保持安静；此轮不依赖 B站登录成功。报告保存在 `reports/social-*.md`，程序必须保持运行。

`qzone_publish` 使用 NapCat 的 `send_qzone_msg` 发布文字或包含链接的 QQ 空间说说，需要支持该接口的 NapCat。`social.qzoneEnabled` 可关闭，`social.qzoneVisibility` 默认 1（所有人），也支持 4（好友）或 64（仅自己）。每小时发布尝试上限由 social.maxQzonePostsPerHour 配置（默认1，0禁发），并计入总发送额度；同文去重，未获得回执不会自动重发。

每次实际读取视频详情时上报 B站历史，工具返回 `historyRecorded`，失败会附原因。热门列表查询不写历史。上报进度为 0，代表浏览记录，不表示已经播放或看完视频。AI 只能给本轮读过的视频点赞，每小时最多尝试 10 次，同一视频去重；不会自动取消点赞。

## 模型可调用的接口

| 工具 | 功能 |
| --- | --- |
| `bili_popular()` | 获取 20 条热门视频候选 |
| `bili_read_video({bvid})` | 获取标题、简介、首分P字幕，并上报历史 |
| `bili_like_video({bvid})` | 给本轮读过的视频点赞 |
| `qzone_publish({text})` | 发布 QQ 空间文字动态 |
| `qq_list_targets()` | 查询好友和群作为分享候选 |
| `qq_send_message({kind,target,text,atUserIds?})` | 向模型选中的目标发送消息，可@目标群成员 |
| `qq_group_members({groupId})` | 查看已查询群的成员，选择@对象 |
| `qq_reply_current({text,mentionSender?,quote?})` | 当前会话回复，支持原生引用和@ |
| `task_create({prompt,delayMinutes})` | 给自己安排一次未来任务 |
| `task_list()` / `task_cancel({id})` | 查看/取消当前会话的任务 |
| `bili_post_comment({bvid,text})` | 在本轮读过的视频下公开发表评论 |

工具定义与权限检查见 `src/tools.js`。模型没有执行系统命令、读取任意本地文件或修改配置的工具。QQ直接回复和B站@回复由程序投递到原会话/楼层。B站主动评论分享看法；QQ分享可附视频链接。本版没有“发B站动态”和“B站私信”工具。

## 已知边界

- 视频理解使用首分P字幕，最长 16000 字符；没有视觉抽帧或语音转写。无字幕/获取失败时，只提供标题简介并明确注明。
- B站只处理视频评论区 @，不处理动态、弹幕或私信 @。只读取最近最多 5 页通知，每个评论楼层核验最多 5 页。通知缺失定位字段或无法核验时跳过并审计，不猜楼层。
- “@我的”网页接口字段需真实账号联调；目前按通知 URI、原生链接与 `item.id` 解析，平台字段变更时应调整 `parseMention`。
- QQ理解文本和图片消息段，暂不读语音或还原收到的引用内容；需 NapCat 配置数组格式。
- 历史是每个会话最近 64 条记录，不是无限长期记忆。私聊/群/视频讨论互相隔离；自主浏览使用独立会话。
- `pending` / `uncertain` 代表上次发送未确认，自动化不会再次发送，需先在平台核实。失败的 @ 最多尝试 3 次。
- 数据与凭据保存在本地，聊天和字幕会发送给你配置的模型服务。分享/回复是账号真实行为，第三方桥接和网页接口可能遇到平台风控。
- 不支持自动开机启动、验证码绕过和登录续期；无登录时不会假装已接入。

### QQ 分条消息

模型使用空行划分消息气泡；长段落按句子拆分，通常每条不超过 240 个字符，链接保持完整。各条间隔约 0.9 秒，引用和 @ 只附在第一条。取消原有 1500 字截断，不再悄悄丢弃长回复尾部。发送前按条数预留总额度；中途失败立即停止并标记状态不明，不自动重发整段。

后台浏览与社交由定时器驱动，不需要收到用户消息。每轮结束后再计时，错误会记录且下一轮继续；启动时输出首轮时间与间隔，后台任务可能等待当前消息处理结束。自主社交仍由 AI 决定对象和内容，也可保持安静。

### 会话上下文

`agent.historyMessages` 当前为 64，控制每个会话保留的最近记录数；`agent.contextMaxChars` 当前为 24000，控制单次请求携带的历史字符数，优先保留较新的内容。这不是模型总 token 上限，当前消息、系统提示和工具结果另外占用上下文。

QQ 私聊、群聊分别保存；未回复的消息和图片描述也能进入历史。成功发送的主动消息会写回接收者会话，工具回复记录实际正文，不记录内部结束语。发送失败不会当成已发送；分条中途失败可能已有部分送达，此时不把整段记为成功。历史保存于被 Git 忽略的 `data/state.json`，重启保留，旧数据兼容；过去已被裁掉的记录无法恢复。模型可看到当前 UTC 时间与最近记录时间。

### 短句、选择性分享与收藏表情

人设默认日常回复 2～10 个字，必要解答可以展开，不按十字强行截断。自主浏览与转发分开判断，整轮不分享是正常结果；是否转发仍由模型决定，不是固定配额。

`qq_list_stickers` 通过 NapCat `fetch_custom_face` 读取账号最多 12 个收藏表情候选，`qq_inspect_sticker` 使用当前视觉模型描述图片，`qq_send_sticker` 只发送本轮看懂的图片，一轮最多一张，计入发送额度。需要先在该 QQ 账号收藏表情；没有合适表情就短句回复或保持安静。支持受信 QQ 图片域名，无法下载或识别的表情不会盲发。发送到当前会话后不再自动追加模型结束语，表情描述会记入对应上下文。新增链路通过模拟测试，尚未做真实账号表情发送验收。

### Harness 接管模式

`runtime: "harness"` 为当前默认值。`npm start` / `start.cmd` 自动启动专用 Harness SDK 子进程，使用现有 `.env` 的模型配置，不需要手动打开 Web UI。QQ 判断回复、图片理解、生成回复、自主浏览和到期任务都调用 Harness；平台收发、定时触发、会话允许范围和发送去重继续由本项目负责。`runtime: "direct"` 可切回原引擎，重启生效。

SDK 使用 `harness-runtime/home/profiles/dafeiyu`，模型密钥只从父进程读取，不写入该配置。只注册本项目的社交工具，没有启用通用终端或文件操作工具。后台任务仍是原来的 10 分钟社交／30 分钟浏览，未另建一套重复定时任务。

现有 `data/state.json` 的有界会话历史继续注入每次 Harness 任务，不需要清空或复制私人聊天。每轮创建独立 SDK 会话以隔离工具状态，执行轨迹写入 `harness-runtime/home/sessions`；`data/actions.jsonl` 中的 `harness-run` 保存对应会话 ID。运行时每 40 次任务回收一次 SDK 进程，轨迹保留。原有额度按真实模型请求计数，判断与识图禁止社交工具调用。

验证包括真实 Harness 工具回调（模拟模型和平台）、真实模型文字请求及生成色块识图；没有为了验收而发布测试评论或 QQ 消息。

## 情绪、关系记忆与主动聊天

`data/state.json` 的 `feelings` 保存开心、难过、烦躁、好奇、精力（0–100），以及每个 QQ 用户的好感（-100–100）、信任、熟悉度和最多 30 条带来源的记忆。聊天先进行一次无工具的情绪/记忆整理；视频实际读取后进行一次感受判断。工具成功、失败和发送也有小幅状态变化；重复事件去重，情绪偏离基线每两小时减半。中性事件不必强行制造喜怒。这是可持续的角色状态，不是模型训练或真实感情。

伤心话题不会降低讲述者的好感；明确友善、恶意冒犯、道歉会小幅调整关系。记忆仅接受当前发送者原话，不保存模型编出的身世。同一QQ号的好感、信任、熟悉度跨私聊与各群共用；当前群通过实际发言记录识别已知成员，换场景不重置关系。

普通喜好可跨会话衔接：记忆整理可从本人原话中额外提取2至60字的 `sharedFact`，只允许普通、适合公开的喜好。代码核验确有原话证据、属于preference，并拦截保密要求和部分敏感格式。当前用户自己的私聊、以及有真实互动记录的群内，可获得该用户的 `sharedPreferences`；跨会话只提供喜好文本，不提供来源、时间、原聊天和私密事件。甲的私聊不会注入乙的记忆。群内原话、私聊原话、睡眠聊天摘要仍只注入原会话；旧版记忆未经新提取不会自动公开。模型的喜好提取可能有误，格式过滤不等于完整隐私识别。

群内合并消息仍保留真实发送者，不把最后一人的身份套给整段聊天。提示要求人格与相处方式保持连贯，群里不透露私聊，与甲私聊不透露乙的私聊，也不解释喜好的私聊来源。模型的理解可能有误，不能将数值当作对人的客观评价。

每 10 分钟的自主社交会优先考虑有过互动、允许联系的好友，按好感和熟悉程度选择，再用该用户自己的历史决定如何开场，也可选择不发。用户需在新版本运行期间有一次互动才进入候选；不会从旧历史臆测关系。默认同一好友主动联系至少间隔 180 分钟，可在 `social.contactCooldownMinutes` 调整（至少 10 分钟）；上次主动消息未得到回复就不继续追发，收到“不要主动联系”等明确反馈后暂停。普通用户请求代发仍走原有工具流程，不套用自主开场的冷却。群聊自主活动保留原有逻辑。

查看状态：`npm run feelings`。查看某人的本地关系和记忆：`npm run feelings -- --user QQ号`。这两个命令只读；详细输出包含私人记忆，不要公开转贴。每批聊天及首次读取视频的语义整理会增加模型调用，失败会记录日志但不阻断正常聊天。保持本地数据目录，重启即可延续；本次改动需手动重启生效。

可通过 `bili_search` 搜索视频，`bili_video_stats` 查询播放、点赞、收藏等快照，`bili_related` 读取相关推荐，`bili_comments` 获取最多 20 条去重评论样本。搜索和统计不会记入观看历史，也不等于看过视频；`bili_read_video` 保留原有资料阅读与历史上报逻辑。

后台自主浏览、社交还可用 `bili_my_history` 查看最近 20 条账号历史，`bili_my_following` 分页读取关注，`bili_my_folders` 列出最多 100 个自己的收藏夹，`bili_my_favorites` 分页读取其中内容（每页 20 条，页码 1–100）。每次验证登录身份，收藏内容限定本人收藏夹。QQ消息和其他scope无法调用这些接口；提示词要求不转述私人来源，只用公开资料独立判断分享价值。这些接口只读，不修改关注、收藏或历史。数据会交给当前配置的模型，Harness本地运行记录可能保留工具结果，相关目录已忽略提交。

兴趣与表达偏好保存在已忽略的本地 `data` 状态中。自主浏览结束后，对本轮实际读取、尚未评价的视频复盘（最多 3 个）；也可主动使用 `self_rate_video`。同一分类至少积累 3 个样本后才注入偏好，每个视频不重复计分。偏好不自动触发点赞或转发。

每个会话累计 8 批合并消息后可复盘表达习惯，两次复盘至少相隔 30 分钟。只接受用户原话中的明确反馈，每次最多调整两个维度，每个维度最多变化 0.05；不同会话独立保存。没有证据就不调整。复盘会消耗额外模型请求，失败不会阻断已完成的聊天。这是持久化偏好记忆，不是训练模型权重，也不保证每次输出都符合风格。

## 睡眠与补觉

当前作息按energy控制，替代旧版固定8小时和熬夜计划：北京时间每晚在23:50至次日00:10内按持久化随机计划入睡，提前10分钟收尾；energy≤10%有95%概率犯困入睡，0%立即强制睡，并至少锁到下一个北京时间08:00–08:30随机时刻（满100%也不提前醒）。每小时恢复10个百分点；普通睡眠80%起允许醒来、100%必须醒，耗尽锁定期间例外；按用户选择不设最短睡眠时长，入睡时精力已满也可立即醒。清醒时可用 `self_set_wake_energy` 将下次醒来阈值设为80–100；未设置时本地随机选择80、90、100之一，整个睡眠过程不调用模型。睡眠状态和阈值跨重启保留，按经过时间结算、不重复恢复；旧熬夜计划自动失效。

清醒基础消耗每小时5个百分点；统计最近一小时实际参与的聊天收发，每条增加0.15个百分点/小时，20条及以上达到每小时8%的上限，频率回落后自动降低。收发消息按ID去重、按实际时间分段结算；工具、看视频、发图等不再额外扣精力，避免突破8%的上限。energy不再像其他情绪自动回归65。低于25%时静默/脑雾总概率从约10%逐渐增至约90%，其中55%为不回复、45%为脑雾，其余正常；≤10%有95%概率入睡，0%立即睡。脑雾限制为短句、慢半拍、不确定就暂停操作，不故意捏造错误事实；该轮不开放工具。睡眠时暂停QQ回复、识图、模型请求、QQ查询、B站/空间查询与互动、浏览器查询和自主任务。独立本地时钟每分钟结算，并在接近午夜时检查当晚浮动计划，不等待模型任务队列；每次查询/发送前再次检查。已在入睡前交给平台的请求无法撤回，但后续请求和消息气泡会被拦截。睡眠期间留言只记本地，醒后不逐条补发。

睡眠期间自动进行本地提取式记忆整理，不调用模型或外部查询：从升级后新增的每条会话记录保留日记（即使超出短上下文上限仍先归档），按北京时间日期、用户/群分别生成部分原话摘录，每会话每日最多2400字；长上下文保留最近12条和有界摘要。完整当天原文以gzip无损归档在 `data/memory/YYYY-MM-DD.jsonl.gz`，当前日原始日记继续保留以接收新留言，过去日期在压缩与索引成功落盘后删除冗余未压缩副本。长期用户记忆仅去除同scope、同内容的重复条目，感情、兴趣与记忆状态另存压缩快照；不把不同用户或群的记忆混合。摘要不等于全文理解，压缩前就已被旧版淘汰的记录无法补回。日志损坏时保留原文并报错，不静默删除。`npm run feelings` 可只读查看最近保存的精力、睡眠状态和整理时间。修改后手动重启生效。

## 本地中文语音


当前机器已安装 Kokoro int8 v1.1，并将 `social.voiceName` 设为 `kokoro-zf_017`（中文女声，sid 11，语速1.04）。也可在 Web“配置 → QQ与声音”选择 `kokoro-zf_001` 或 `kokoro-zf_036`。这是按清亮中文女声方向选择的候选，没有目标声音样本，不能保证是视频中的同款声音。模型来源：[Kokoro-82M-v1.1-zh](https://huggingface.co/hexgrad/Kokoro-82M-v1.1-zh)，Apache-2.0，本地 CPU 合成，无需语音 API 密钥。

新电脑先 `npm install`，再运行 `powershell -File setup-kokoro.ps1` 下载官方 sherpa-onnx 模型包（约147 MB），校验固定 SHA256 后解压。模型存于已忽略的 `data/tts`，不提交 Git，再把 `social.voiceName` 改为 `kokoro-zf_017`。`npm run voice:preview` 按当前配置生成 `data/tts/preview.wav` 本地试听，不发送 QQ。Kokoro 输出24000 Hz单声道 PCM WAV；Windows 的 eSpeak 不支持中文绝对数据目录，因此仅在隔离合成子进程内切换到模型目录，使用相对发音数据路径。

原 `chaowen`（安装脚本 `setup-voice.ps1`，22050 Hz）和 Windows `Microsoft Huihui Desktop` 仍可选择；新安装示例配置保留 chaowen。模型缺失或合成失败会报错，不悄悄换音色。切换后重启大肥鱼生效。

Web 右上角“外观”支持浅色、暗黑、跟随系统；默认跟随系统，实时响应系统变化，偏好只保存在当前浏览器。新代码首次加载需重启面板并刷新页面。

合成在独立子进程执行，最长 60 秒，不阻塞消息接收。已有 QQ 发语音工具、发送限额和睡眠拦截继续生效；验收包含真实本地合成和非静音检查，未向真实联系人发送测试语音。后台仍由用户手动启动。

## 自主处理好友申请

接收 NapCat 实时上报的 `request/friend` 事件，清醒时每分钟检查（启动首轮10秒），每轮最多3项。模型结合申请人的好感度、信任、熟悉程度和本人的私聊上下文决定同意或拒绝；陌生人按中性好感0处理。审批仅使用收到的真实flag调用 `set_friend_add_request`，不向模型开放主动添加好友接口，也不自动发送欢迎消息。接口说明：https://napcat.apifox.cn/226656932e0 。

睡眠期间申请保存在本地，醒后继续；重启保留，重复事件去重。格式错误不默认同意，连续3次判断失败留待人工处理；平台操作超时或失败标记不确定，不自动重发。每小时最多20次审批，超过7天的待办不自动处理。本功能不补抓升级前的历史申请；需要NapCat连接期间收到新申请事件。验证采用模拟申请和接口，未处理真实好友申请。

## B站点赞、评论、收藏、文字动态与操作留存

除观看视频外，本程序通过B站客户端执行的查询及互动会追加到 `data/bilibili-activity.jsonl`：搜索、热门、数据/评论/相关推荐查询、账号历史/关注/收藏夹读取、@通知与楼层核验、点赞、评论（含自动回复@）、收藏、发动态。操作开始先保存意图，完成后保存状态；评论和动态保留完整提交正文以及平台回执，读取操作保留目标参数和数量摘要。日志没有自动清理或条数上限，不记录Cookie、CSRF和请求头。观看资料读取及观看历史上报不额外写入此日志，原有观看历史、浏览报告及技术审计保持原样。本功能只记录程序自身执行的动作，无法记录你手动登录账号后的操作，也不追溯升级前记录。

查看最近50项：`npm run bili:activity`；完整日志就在上述文件。只有开始而没有完成的记录代表进程可能中断，不能视为成功；网络故障或缺少写入回执标为uncertain，明确平台错误标为failed。记录在已忽略的data目录中，重启保留。应用需手动重启后开始使用新功能和留存。验证使用模拟平台响应，未向真实B站发布测试评论、动态或收藏。

接口核对来源：收藏 https://github.com/melon-444/bilibili-API-collect-fork/blob/master/docs/video/action.md ，文字动态 https://git.xfe.studio/XFEstudio/bilibili-API-collect/Blob?branch=master&path=docs%2Fdynamic%2Fpublish.md 。

`bili_follow_up(bvid)`：关注本轮真实读取视频的作者，使用视频资料核验的authorId，不由模型填写陌生UID。先检查当前关注关系，已关注/互粉直接返回；不会关注自己或改变黑名单。每小时最多10次尝试，按作者UID持久化去重，失败或超时不自动重发；睡眠与专用任务范围限制继续生效。操作意图、作者UID、结果及回执追加到同一份B站日志，`npm run bili:activity` 可查看。接口依据：https://github.com/realysy/bili-apis/blob/master/docs/user/relation.md 。

QQ闲聊回复会额外提供最多12张已理解、已收藏的表情候选（ID和简短描述），供模型直接调用图片发送工具，降低每次重新查找表情的成本。提示词鼓励更积极地按具体语境选择表情，偶尔在文字短句末尾放一个颜文字；不强制每轮发送，也不随机硬塞图片或文字。只发一张图也算完成回复，原有消息去重和隐私范围继续生效。此调整需手动重启，实际使用频率由当前模型结合对话决定。

## 梦境与醒后查看未读

睡眠满30分钟后，每次睡眠有一次40%的本地做梦机会，梦境是几种轻量随机想象场景，不调用模型或外部接口，也不抽取其他人的私聊。醒后保留最近一次入睡/醒来时间、时长、原因、开始/结束精力和可选梦境，最近14次睡眠留在本地状态；每次对话会提供最近睡眠经历，让模型区分“刚醒”与“之前睡过”，梦只当梦。可通过 `npm run feelings` 查看最近保存的睡眠信息与未读数量。

睡眠期间收到的QQ私聊/群消息进入持久化未读箱，全局仅保留最近99条，超过时淘汰最早的待查看项（完整聊天归档继续保留）。相同消息去重；醒来并连上QQ后，最多15秒内安排查看，也会在处理新的实时聊天前先查看积压。按会话分别合并，长消息分批避免截断，再由原有参与判断选择是否回应，不逐条刷屏、不混合不同私聊的记忆。睡着时不读取未读、不下载图片；图片待醒后如有需要才识别。程序离线期间没有收到的QQ消息、升级前未进入新未读箱的留言无法自动补抓。

查看前保存认领状态，重启不重复处理已认领批次；模型或平台状态不明不自动重发，错误记录在本地审计。若尚未发送就重新入睡，未处理项回到未读箱。梦境和未读箱均在已忽略的data目录中，修改后手动重启生效。

### 困倦、耗尽锁定与睡醒问候

低精力的入睡概率在每次醒来时本地抽取：95%的周期会在精力降至10%时入睡，其余周期可以坚持到0%；阈值持久化，不因反复调用查询而重抽。0%必须立即进入耗尽睡眠，最早到下一个北京时间08:00–08:30随机时刻才能醒，且仍需达到设定的80%–100%精力。普通犯困和夜间入睡仍按原恢复阈值醒，不统一锁8点；不允许超过当晚计划继续熬夜。

睡前5分钟内有实际互相收发消息的QQ会话，会在切换成睡眠状态前尝试发送单条“我先睡啦，醒了聊”。只在真实入睡当时发送，不为离线补算的历史入睡补告别；受发送额度、回执和去重约束，失败不会虚报成功。睡眠期间不再发送或查询。醒后先看未读，再仅对一处睡前活跃会话自主判断是否短问候；已经继续聊上、收到新消息、用户暂停联系、醒来太久或很短的休息均跳过，不广播。问候判断在清醒后才调用模型，最多一次，拒绝发送也是正常结果。

QQ表情候选改为从整个已收藏图库筛选最多12张，不再被最近30张普通照片挤掉；优先提供近期未用过的图片，成功发送后记录使用时间。提示词鼓励轻松聊天更频繁地发真正的QQ图片表情包，仍按图片含义选择，不随机硬塞或用文字占位冒充图片。以上修改需手动重启。

## 发布限额与回复概述日志

在config.json里设置 `social.maxQzonePostsPerHour`（QQ空间）和 `bilibili.maxDynamicsPerHour`（B站动态），均为最近一小时的发布尝试数量上限，默认1；非负整数，0表示禁止发布，不表示无限。两平台独立计数，并继续受 `agent.maxOutgoingPerHour` 总发送限额限制。同文去重不重复占名额，本地额度不足不会把尚未请求平台的内容标成发送不确定。修改后手动重启生效。

`logging.replySummary` 默认true，后台输出例如 `AI回应概述（参与判断，qq:user:...）：对方延续话题，选择接话`，以及回复生成时的一句话回应意图/表达选择。概述由本次模型调用直接返回，不额外请求模型；QQ、B站@回复、空间评论、自主私聊均已接入。完整内部推理/系统提示词不作为该功能的日志内容。概述单行最多120字，已知API密钥和NapCat Token会隐藏，另保存为data/actions.jsonl的reply-summary审计条目，便于本地查看。关闭开关时不输出该概述。

生成回复时模型使用reply/summary封装，程序仅把reply交给聊天发送与会话记忆；summary仅进入后台日志。模型未提供概述时会明确标注，不根据正文编造理由；封装损坏时阻止把内部字段发给用户。该日志说明模型表达的简要决策与回复意图，不是完整思考过程，也不是平台发送成功的依据，成功与否仍看工具回执。

## 本地 Web 管理面板

双击 `start.cmd` 或运行 `npm start`，会启动管理面板及大肥鱼，不会自动打开网页，可手动访问 http://127.0.0.1:3081/ 。面板与DeepSeek Harness原有3080端口独立。页面含状态总览、配置设置、运行日志、B站足迹和用户记忆；显示精力/睡眠/未读、任务、回应概述，支持常用字段表单与完整JSON配置编辑。密钥依旧保存在.env，面板不提供凭据读取或编辑接口。

面板内容区随可用窗口宽度展开，支持宽屏及手机。用户记忆页先显示可搜索的用户目录，包括QQ号、昵称、好感、信任、熟悉度和最近互动时间；点击用户后才加载其长期记忆、来源会话、可共享喜好、最近保存的私聊记录以及最多12份睡眠整理摘录。群聊记忆保留来源，但不把整段群聊中其他人的发言混入该用户的聊天记录。详情是本机管理员只读查看，不会改变AI的跨会话隐私规则；已从近期历史移除的完整原文仍在原有压缩归档中，本页不解压展示全文。

用户目录支持列表/网格切换并记住选择，可筛选全部、未屏蔽或已屏蔽用户。好感图使用环形扇区与中央数字：数值范围-100至100，弧长表示绝对值，负值同时显示负号及红色，不只依赖颜色辨认。

睡眠整理新增每用户记忆清单：在本地整合已有长期证据、完整可归属的私聊日记、新版群聊真实发送者的记录及针对该用户已确认的空间点赞/评论，再按私聊与各群分区写入 `data/user-memory/<QQ号>.json.gz`。首次整理也会回填现有私聊归档；旧群日记无法可靠归属时只保留已核实属于本人的事实，不猜测发言者。每天新增记录按事件去重合并，重复睡眠不重复添加；已有清单不自动截断，管理员修改的内容保留，旧源记录不会覆盖修订。此过程不请求模型、不查询平台，采用保留原话的清单合并，不等同于模型语义总结。

模型仅接收当前会话来源的有界清单摘录，详细旧事可通过 `qq_search_user_memory` 关键词检索，不把整份原文放入上下文，也不能跨用户或跨群查询私人清单。Web用户详情可选择来源、编辑清单，以及调整好感/信任/熟悉度；有版本冲突时拒绝覆盖，保存后新回复即时使用。后台和Web通过独立控制文件协作，Web不会直接覆盖运行中的state.json；每个压缩资料带锁及删除代际校验。

“屏蔽此用户”仅在程序内屏蔽QQ私聊、群聊发言、好友申请和空间评论处理，保留QQ好友关系及已有记忆，支持解除。会在消息接收、合并处理、睡眠未读和发送前检查，屏蔽用户不会再成为主动联系对象。“删除用户记忆”清除AI可用关系、私聊历史/摘要、压缩清单、私聊素材和便签，并从普通记忆归档/快照移除该用户；为避免旧群上下文仍引用他，涉及的群短期上下文也会清空，其他人的独立用户档案保留。操作需确认且不可撤销；删除不等于屏蔽，之后新的消息会从中性关系重新认识。删除时间标记防止旧日记在整理时恢复档案，正在生成的旧回复会取消；已送达的消息无法撤回。操作审计与Harness执行轨迹仍保留用于诊断，不作为用户记忆重新导入。

角色提示词页直接读取和保存项目的 `persona.md`，最多30000字，支持字符计数、未保存提示、冲突检测与恢复旧版。每次保存修改前会将原文备份到已忽略的 `data/persona-history/`，保留最近10份；载入备份只填充编辑器，点击保存才覆盖文件。提示词修改需重启大肥鱼生效。配置页增加执行引擎、上下文、模型输出与工具轮数、QQ消息合并、主动联系间隔、B站轮询/评论额度、浏览器路径和面板启动选项；完整JSON编辑仍保留。API密钥及账号Token继续放在.env中。

组件中心提供6个现有能力开关（公开网页、匿名逛店、语音、本人头像、QQ空间、B站），以及4个随项目附带、默认未启用的MCP组件。点击“安装并启用”会在config.json的components中注册这些已附带的实现，不从互联网下载未知代码。新请求即时读取开关，关闭后既不向模型提供工具定义，也拒绝直接调用；已经发出的请求可能完成。B站与空间定时查询也会跳过关闭的对应组件。基础平台开关仍有效，组件不能越过睡眠或原有发送限制。

MCP组件包括：计算与时间（纯数学解析及真实时区时间）；私人便签（每个私聊/群分别保存，最多100条、每条4000字）；RSS阅读（在组件卡片配置最多10个公开RSS/Atom源，只读取实际条目，拦截本机/内网与重定向）；Windows应用（仅查询或启动记事本、计算器，不读取、操控窗口，不执行任意命令，启动限后台自主活动且每小时最多3次）。组件调用总计每小时最多60次，便签保存在data/components专用目录。

普通模型和Harness共用ComponentManager，通过标准MCP stdio的initialize、tools/list与tools/call连接本地组件服务；Harness先经现有社交工具桥接再进入MCP，不会把第三方服务器直接置于睡眠和会话权限检查之外。组件服务已与Harness附带的官方MCP SDK完成兼容验证，也测试了同一个Harness进程内启用、调用并关闭组件。当前版本不支持从Web输入任意npm包、Shell命令或第三方MCP服务器；扩充目录需新增受审查的组件实现。首次升级须完整重开start.cmd，之后组件开关无需重启；提示词和常规程序配置仍需重启后台。

QQ足迹页只记录QQ空间发布动态、动态点赞、动态评论和回复评论，可按操作类型筛选，显示时间、目标动态、公开正文与执行状态。记录写入独立的 `data/qq-activity.jsonl`，不采集QQ聊天、资料查询和空间浏览；开始请求与结果共用操作ID，页面合并成一条。中断或超时标记为结果不确定，不能当作成功；重复操作跳过，不重复执行。记录从新版运行起积累，不追溯猜测旧操作结果。升级后需完整关闭并重新运行 `start.cmd`，再刷新浏览器，才能加载新的面板接口及后台记录逻辑。

面板可启动、停止、重启自己管理的大肥鱼子进程。停止与重启使用IPC请求正常退出，等待当前队列及Harness关闭后再启动新进程；不会杀死其他窗口手动启动的实例。若此前大肥鱼仍在旧终端运行，请先Ctrl+C停止旧实例，再打开新start.cmd。关闭浏览器标签不停止后台；在启动终端Ctrl+C会关闭面板并请求大肥鱼退出。重启时保留data目录和面板最近日志。需要仅运行机器人时可用 `npm run start:agent`。

保存配置会校验类型/数值，冲突时拒绝覆盖另一个窗口的新配置；保存后点击面板的“重启”使机器人配置生效。web.enabled默认true，web.port默认3081，web.openBrowser默认false（设为true可恢复自动打开网页）；面板自身端口/开关和.env变更需重新打开start.cmd。仅监听127.0.0.1，接口需当前页面的临时会话令牌，写操作校验本机来源，不对局域网或公网开放；不要把面板反向代理到公网。界面只读取本地状态和日志，睡眠期间查看面板不会唤醒或触发平台查询。

面板最多保留启动后600行控制台日志，B站页面读取日志尾部最近150条事件；完整持久化审计仍在data中。后台停止时状态卡片展示最近保存的记录，并明确标记来源，不伪装成实时运行。界面已在1280宽桌面、375宽窄屏检查；配置保存与本机访问约束经过接口测试，进程启动/IPC停止/等待退出再重启使用独立测试子进程验证，未启动真实机器人进行界面测试。

### Windows状态文件替换失败

状态保存改为同目录唯一临时文件（进程ID和随机ID），完整写入并同步后原子替换；EPERM、EACCES、EBUSY等替换错误最多尝试8次，累计等待约1秒，适应Windows短暂文件占用。不会通过先删除原文件来规避报错。持续失败时保留原状态和本进程最新的完整恢复副本，日志会给出副本路径；下一次成功保存后清理该恢复副本。磁盘满等非瞬时写入错误不反复重试，未写完整的临时文件会清理。

Store.save仍同步完成：操作的pending状态未能落盘时，不会执行后续发送，避免重启后重复操作。QQ消息回调的同步抛错与异步拒绝统一记录为“QQ处理失败”，不再因Promise.resolve在调用回调之后才包装而逃逸为event_target异常。面板配置保存也使用同一替换策略。验证包含模拟短暂/持续占用、磁盘写满、原文件完整性、恢复副本和回调失败后继续接收消息。

## 情绪扩展与深圳天气

用户列表、网格、详情均以扇形图与中心数字展示好感（-100～100）、信任和熟悉度（0～100）。每位用户另有亲近、关心、感激、自在、戒备、玩闹意愿、欣赏七项相处感受，在用户详情可查看并编辑。这些表示她对这个人的角色状态，不是测量人类用户的心理。聊天复盘必须引用本人原话，按支持、帮助、夸奖、开心分享等证据小幅变化，事件去重，数值0～100，私聊与群保持同一关系但不泄露私人起因。旧数据自动补齐。

她自己的情绪在开心、难过、烦躁、好奇、精力之外增加平静、兴奋、担心、温柔、自信、无聊；聊天、视频阅读感受、工具活动及天气会更新相应指标。自身短期情绪逐渐平复，精力仍只按既有清醒消耗与睡眠恢复规则管理。Web总览展示完整情绪。提示词引导按语境调整表达和活动，不机械报数，不以心情强迫他人回应。

天气使用 [Open-Meteo](https://open-meteo.com/en/docs)，无需密钥。当前已配置广东深圳，后台清醒时首轮5秒后尝试更新，此后每分钟检查缓存，默认30分钟刷新；睡眠时不查询。读取温度、体感、湿度、降水、风速、昼夜和天气类型，附数据时间。天气是区域模型估计，不是用户所在地或窗外实测；超过刷新间隔标记待更新，超过2小时不作有效天气注入。失败保留原数据但不伪造新天气，5分钟退避，重名城市通过省份区分。天气只轻微改变自身情绪，不扣用户好感，不改睡眠或精力。

在Web“配置设置 → 本地天气”可修改开关、城市、省份、国家代码、刷新间隔（15～180分钟），保存后重启生效；同样可编辑config.json的weather对象。模型可用local_weather读取同一受限缓存，两种模型引擎均会收到天气语境，按天气、心情与话题自主选择聊天、浏览、表情或安静待着，不固定播报、不广播提醒。

## 动态生活状态与睡前收尾

Web“状态总览 → 调整精力、情绪与消耗”可动态设置当前精力、全部自身情绪、基础消耗、聊天最高消耗和睡眠恢复速度。新增期待、孤单、害羞、挫败、安心、灵感六项情绪，随实际互动变化。只提交编辑过的字段，0～100的数值会在后台下次检查时应用（通常一分钟内），无需重启；表单编辑期间不会被自动刷新覆盖。消耗/恢复速度为每小时百分比，默认5、8、10；均须大于0且不超过100，最高消耗不能小于基础。

Web使用独立data/life-controls.json原子保存，后台是state.json唯一写入者。消耗速度按变更时刻分段结算，手动情绪仅应用一次，之后继续自然变化；后台停止时先保留设置，下次启动时应用。精力改成0会立即触发耗尽睡眠，已耗尽锁到8点的睡眠不能靠补精力提前解除。

每晚计划在北京时间23:50–次日00:10之间随机选择并持久化，重启不重抽。前10分钟逐渐减少接话，暂停新开主动聊天与自主视频浏览；睡前告别仅考虑最近5分钟内真正回复过且双方都有消息的会话，被动群消息或普通主动分享不算正在聊天。每晚最多两个会话、每处一次，不因启动、旧消息或离线补算补发晚安；正式睡眠后完全静默。0%耗尽仍立即入睡，不为告别强撑。

睡眠上下文明确给出已醒分钟数，历史睡眠不再称作刚经历。醒后主动问候窗口缩至30分钟，自动问候仍一次、最多一个会话；自称刚醒/刚起床仅醒后15分钟内，早安仅北京时间05:00–10:59。模型最终回复、QQ发送和语音工具也检查过时说法，避免旧历史持续诱发起床问候。

## 精力情绪耦合与私聊操作权限

低精力阈值更新为10%：每次清醒周期本地抽取，95%的周期到10%即入睡，5%可继续到0%，0%必定耗尽睡眠并锁到下一个北京时间08:00–08:30随机时刻。概率结果持久化，升级时迁移旧3%～5%阈值，不因重复请求反复抽签。

当前情绪表现由基础情绪和精力共同计算。65%精力为中性强度，10%时积极情绪约为基础值28%，100%时约125%（上限100）；开心、好奇、兴奋、自信、期待、灵感、安心、温柔随精力变化，低于25%另增加少量疲惫烦躁与挫败。基础情绪仍保留聊天、视频和天气带来的变化，恢复精力可逆，不反复乘法扣减，不影响任何用户好感。Web总览和模型上下文展示当前表现，生活编辑器修改基础情绪。

天气情绪分别考虑实际温度、体感温度、湿度、风速、昼夜、降水和雷雨；单次每项变动最多5，每天气小时只记一次，不改精力或用户关系。群聊按真实发言者证据复盘，实际读取的视频按模型阅读感受更新情绪，不能把标题当已看过画面。

私聊操作权限按qq.adminUsers里的QQ号核验，不认昵称、消息里自称爸或引用授权。非管理员私聊仅正常聊天、读取当前会话记忆和表情素材、向当前用户发文字/表情/图片/语音；其他查询和操作均不开放，包括第三人代发、头像、空间/B站互动、账号操作、任务、浏览器、购物和MCP组件。工具列表按会话过滤，执行入口再次检查目标与身份，真实Harness越权回归已覆盖。管理员私聊和自主生活仍保留原能力及其他限制；非管理员请求不得被当作自主计划执行。

## 虚拟健康与模拟心率

Web状态总览新增虚拟健康（0～100，默认90）与模拟心率（bpm）。生活状态编辑器可以动态修改健康值、模拟心率基准（40～120，默认66），沿用版本冲突检查、独立控制文件和后台单写者，不需要为修改数值重启。心率基准是角色参数，显示心率还会随精力、睡眠、情绪与最近聊天活动计算变化，显示范围40～150，仅用于虚拟角色模拟，不是实际生理测量或医疗指标。

健康按经过时间结算：睡眠每小时恢复2点，清醒无明显压力时每小时轻微恢复0.15点；低于35%精力与较高担心/烦躁会增加消耗。不回算功能安装前的虚构健康历史，重复tick不会重复恢复。睡眠切换和消耗修改按分段时间处理，值始终限制0～100。最近60个分钟样本保存在state.health.history，重启保留。

健康低于40时额外提高安静不接话的概率，低于25时暂停定时自主社交和视频浏览，提示词引导少折腾、优先安静休息；健康不会绕过既有睡眠、精力阈值、耗尽锁定或权限规则，也不扣任何用户的好感。健康与心率仅作为角色状态使用，不虚构真实疾病或要求用户为身体状况负责。
